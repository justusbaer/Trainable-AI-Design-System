1. System Topology & Dual-Surface Philosophy

Architecture

Modern AI coding tools suffer from a fundamental tension between cognitive overload and style hallucination. Providing full Storybooks to an LLM exhausts its context window, while providing unstructured text guidelines leads to models inventing raw hex values (#2563eb) and breaking spacing scales.

Trainable DS resolves this with an Agent-Native, Dual-Surface Architecture:

🌐 1. Extraction & Ingest
  • • Headless Chrome CDP (Port 9222)
  • • Shadow DOM SVG piercer
  • • @font-face WOFF2 harvester
  • • Multi-Modal Ingestion Adapters
⚙️ 2. Core & Compiler
  • • CAM16 / OKLab Color Math
  • • 14-Tone M3 Palette Generator
  • • Discrepancy Analyzer (Convergence)
  • • FusionEngine Precedence (50→10)
🌿 3. Version Control
  • • Git-Native Store in .tds/vcs/
  • • SHA-256 Commit & Snapshot Hash
  • • AST-Aware 3-Way Semantic Merger
  • • MergeGatekeeper (WCAG & Touch)
🤖 4. Dual-Surfaces
  • • Machine: llms.txt & DESIGN.md
  • • Machine: tokens.json & MCP Server
  • • Human: overview.html Review Studio
  • • Lock protection: tds:locked = true

💡 Core Architecture Philosophy
Machine-First, Human-Governed: AI agents consume terse, high-density machine artifacts (DESIGN.md, tokens.json, and JIT MCP tools). Humans review and override decisions through visual sliders in overview.html. Any human override is permanently stamped with "tds:locked": true, rendering it immune to crawler overwrite.

Standard RGB calculations fail human perceptual uniformity. Trainable DS implements an analytical bridge between sRGB, Linear sRGB, and OKLab / CAM16 in @trainable-ds/core/src/hct/palette.ts:

1. sRGB to Linear sRGB:
C_linear = (C / 255 ≤ 0.04045) ? (C / 255) / 12.92 : ((C / 255 + 0.055) / 1.055)^2.4

2. Linear sRGB to Cone Responses (L, M, S):
L = 0.4122214708*R + 0.5363325363*G + 0.0514459929*B
M = 0.2119034982*R + 0.6806995451*G + 0.1073969566*B
S = 0.0883024619*R + 0.2817188376*G + 0.6299787005*B

3. Non-Linear Cube Root Compression:
L' = cbrt(L), M' = cbrt(M), S' = cbrt(S)

4. Web Extractor & Deep Visual Alignment

@trainable-ds/compiler/aligner

4.1 Headless Chrome CDP & Shadow DOM Harvester

The extractor launches a headless Chrome instance (CdpRunner) on remote debugging port 9222. To harvest modern enterprise web applications built with Web Components, it recursively pierces shadow roots:

Recursive Shadow DOM Harvester (assets-harvester.ts) 
function harvestIconsFromRoot(root) {
  const candidates = root.querySelectorAll('svg, ds-icon, [class*="icon"], [data-icon]');
  candidates.forEach(el => {
    let svgEl = el.tagName.toLowerCase() === 'svg' ? el : null;
    if (!svgEl && el.shadowRoot) {
      svgEl = el.shadowRoot.querySelector('svg'); // Pierces Shadow Root
    }
    if (svgEl) {
      const viewBox = svgEl.getAttribute('viewBox') || '0 0 24 24';
      const hash = viewBox + '_' + svgEl.innerHTML.slice(0, 80);
      rawIcons.push({ name: el.getAttribute('name') || 'icon', viewBox, svg: svgEl.outerHTML });
    }
  });
  // Recurse into all nested child shadow roots
  root.querySelectorAll('*').forEach(child => {
    if (child.shadowRoot) harvestIconsFromRoot(child.shadowRoot);
  });
}

4.2 Discrepancy Analyzer & Convergence Formula

The discrepancy analyzer audits the extracted tokens against computed styles sampled from live elements. The composite convergence score is calculated using the weighted formula:

Composite Convergence Score:
CompositeScore = clamp(Geometry * 0.35 + Color * 0.30 + Typography * 0.20 + Material * 0.15)

Deduction Rules:
• Geometry: Shape mismatch (Pill 9999px vs Rounded Rect) = -35; Corner radius drift > 4px = -15
• Color: Euclidean RGB distance > 15 = -25
• Material: Opacity / Alpha drift > 0.20 = -25
• Typography: Font family mismatch = -25; Font weight drift > 150 = -15

5. Universal Ingestion & Git-Native VCS (DS-VCS)

@trainable-ds/compiler/vcs

5.1 FusionEngine Precedence Order

When ingesting design system data from multiple sources (CSV tables, markdown brand guidelines, screenshots, and conversational refinements), the FusionEngine applies strict source priority:

1. Conversation (Priority 50) — Explicit engineer directives (highest priority)
2. Table (Priority 40) — CSV / TSV / Figma Tokens Studio JSON
3. Web (Priority 30) — Computed styles sampled via Chrome CDP
4. Document (Priority 20) — Markdown brand guides & DOs/DONTs
5. Vision (Priority 10) — Screenshots & OKLab color clustering

5.2 Git-Native Design System Version Control

The system maintains an immutable, content-addressed version control store in .tds/vcs/:

  • SHA-256 Snapshots: Snapshots are serialized and hashed to 16 hex characters in .tds/vcs/snapshots/{hash}.json.
  • Cryptographic Commits: Commit objects contain id (12 hex chars), parentId, branch, timestamp, and snapshotHash.
  • AST 3-Way Semantic Merger: Reconciles branch changes at the token and component AST level, isolating conflicts without JSON corruption.
  • MergeGatekeeper CI Gate: Automatically blocks merges if color contrast < 4.5:1 (WCAG AA) or touch targets < 48px.

The evaluator runs four deterministic audit tiers with automated point deductions:

Tier 2: Component Reuse TDS-REINVENTED-COMPONENT HIGH -15 pts Import certified component (e.g. <Button>) instead of raw <button>

Tier 4: Content & Case TDS-CAPITALIZATION-NOT-SENTENCE-CASE MEDIUM -8 pts Change Title Case ("Save Changes") to sentence case ("Save changes")
